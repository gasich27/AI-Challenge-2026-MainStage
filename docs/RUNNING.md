# Как запускать

Для просмотра результатов ничего обучать не надо: открой README метки, её журнал и сохранённые выводы ноутбука. Общая таблица — [results.csv](results.csv). В ней validation и internal test идут отдельно.

Для запуска кода нужна вся папка проекта, включая `src/`, а не только один `.ipynb`. Открывай каждый ноутбук в отдельном kernel и запускай сверху вниз.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/check_project.py
python scripts/build_reports.py
python scripts/interpret_models.py
```

`build_reports.py` читает сохранённые вероятности, пересчитывает метрики и строит графики. Он не обучает модели и не меняет пороги. Тест split требует локальный `data/train.csv`. Проверка проекта работает и без датасета.

`interpret_models.py` дополнительно требует сохранённые геометрические модели, CSV признаков и PNG. Он сверяет предсказания, считает SHAP на 128 объектах и сохраняет примеры ошибок.

## Какие файлы нужны

| Задача | Файлы вне Git |
|---|---|
| EDA и извлечение геометрии | `data/train.csv`, `data/train/*.npz`, для примеров — PNG |
| Старые baseline | `archive/artifacts/` с CSV и JSON, `archive/models/` с весами |
| Геометрия по меткам | исходные NPZ либо готовые CSV в `labels/*/artifacts/`; модели в `labels/*/models/` |
| DINOv2 | embeddings, manifest и done mask; таблицы геометрии и конфиги из предыдущих опытов |
| Сравнение simple | ещё нужны файлы из `simple_dinov2_comparison_assets.zip` и сохранённая DINOv2 модель |
| Internal test | отдельные embeddings и признаки для 1344 объектов; они не заменяют train/validation кэш |
| MIL | PNG или `data/train_png.zip`, GPU, доступ к весам DINOv2; старые глобальные embeddings не подходят |

На этой машине есть данные и геометрические кэши. Часть результатов DINOv2 сохранилась только в выводах скачанных Colab-ноутбуков. Наличие такого вывода не означает, что все нужные веса тоже есть локально. Перед запуском смотри проверки файлов в начале конкретного ноутбука.

## Colab

Положи проект в Google Drive вместе с `src/`, данными и нужными моделями. Подойдёт прежняя папка `Colab Notebooks/colab_upload/AI challenge main`. Если путь другой, стартовая ячейка попросит его ввести. Старые ZIP с данными не содержат новый `src/`: загрузи эту папку отдельно.

Для ResNet, DINOv2 и MIL включи GPU. На CPU можно смотреть результаты и работать с CatBoost. На видеокарте с 4 ГБ начинай с маленького batch. У MIL извлечение идёт по двум объектам и небольшими порциями ракурсов; при нехватке памяти размер порции уменьшается. Его patch-кэш занимает около 2.25 ГБ и создаётся на диске Colab. После удаления среды этот локальный кэш пропадёт.

DINOv3 пока не запущен: доступ к весам не был одобрен. Не нужно ставить его зависимости для остальных опытов. Не сохраняй токен в коде или выводах ноутбука.

## Что значит повторный запуск

Геометрические ячейки используют готовые CSV и досчитывают недостающие объекты. Перед заменой алгоритма нужен новый файл кэша: старые числа относятся к старой формуле. Выравнивай строки по `item_id`, не по номеру строки.

Ячейки с `model.fit()` запускают обучение и могут перезаписать модель в указанной папке. Если нужны только прежние результаты, используй отчёты. Единого скрытого переключателя для всех опытов нет: порядок действий виден прямо в ноутбуке.

Embeddings можно переиспользовать только при совпадении UUID, порядка объектов, модели, её версии и обработки изображений. Общая проверка находится в `src/data.py`. Для новых кэшей сохраняй эти параметры в manifest. У старых геометрических CSV полного manifest нет — один размер таблицы не доказывает совместимость.

Версии установленных библиотек записаны в [environment.json](environment.json). Это среда проверки, а не обещание побитового совпадения на другом GPU. `requirements.txt` задаёт совместимые диапазоны; исторические Colab-среды полностью не зафиксированы.
