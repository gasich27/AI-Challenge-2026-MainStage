# Что именно считаем

Это описание кода, который уже есть. Формулы не менялись при рефакторинге.

## Разбиение и метрики

Сначала выделяем 15% объектов с `random_state=42`, потом 17.65% оставшихся с `random_state=43`. Оба раза используется multilabel stratification по всем 11 меткам. Получается 6259 / 1361 / 1344. Порядок строк исходного CSV тоже важен. Разбиение по UUID не защищает от похожих объектов с разными UUID: отдельной группировки по геометрическим дублям здесь нет.

Вероятность переводим в класс как $\hat y=\mathbb{1}[p\ge t]$. Порог выбираем только по validation. Сетки порогов в исторических опытах отличаются; они сохранены в коде, а не заменены одной новой сеткой.

$$P=\frac{TP}{TP+FP},\quad R=\frac{TP}{TP+FN},\quad F1=\frac{2TP}{2TP+FP+FN}.$$

При нулевом знаменателе P/R/F1 возвращаем 0. AP считаем по вероятностям; без положительных примеров он не определён и записывается как N/A. ROC-AUC тоже N/A, если остался один класс.

Для общей задачи $score=10F1_{quality}+10F1_{defects,weighted}$. В старых общих таблицах показан `score/20`. Результаты отдельно выбранных моделей меток нельзя просто сложить и назвать проверенным общим score.

## Базовые mesh-признаки

Для треугольника $A=\frac12\|(v_1-v_0)\times(v_2-v_0)\|$. Длина ребра $l=\|v_i-v_j\|$, диагональ bounding box $d=\|v_{max}-v_{min}\|$. Относительные длины делим на $d$, площади — на $d^2$, с защитой знаменателя в коде. Коэффициент вариации — отношение стандартного отклонения к среднему.

В старом CatBoost площади и рёбра оценивались по выборке до 5000 граней. Площадь всей поверхности там приближённая. Полный baseline не рассчитан на любые повреждённые входные файлы: новые извлекатели отдельно возвращают статус ошибки и NaN. Менять старую формулу при сохранении старых моделей нельзя.

## lowpoly

Новые признаки используют до 12000 граней: четыре непрерывных участка списка. Соседние грани ищем по общему ребру из двух индексов. Для угла берём только рёбра, у которых ровно две грани. Границы и non-manifold рёбра считаем отдельно.

$$\theta=\frac{180}{\pi}\arccos(|n_1\cdot n_2|),\quad 0\le\theta\le90^\circ.$$

Модуль делает признак нечувствительным к направлению нормали. Поэтому это не ориентированный угол сгиба: переворот грани он может скрыть. Среднее с весами по рёбрам: $\sum l_e\theta_e/\sum l_e$.

`curvature` в коде — $\theta_e/\max(l_e/d,10^{-9})$, а не точная дифференциальная кривизна. `normal_variation` — средний угол соседних граней для каждой грани, после чего считаются перцентили по граням.

Локальная PCA использует до 15000 вершин, до 128 запросов и 24 соседей. Её показатель — $\lambda_{min}/\max(\sum\lambda,10^{-15})$. `triangle_aspect` — отношение самой длинной стороны к самой короткой, а не отношение радиусов окружностей.

У выбранных участков появляются искусственные границы. Поэтому `boundary_edge_share` на большом меше нельзя читать как точную долю дыр во всём объекте. Плотность `faces_per_bbox_volume` равна $N_f d^3/V_{bbox}$; для почти плоских мешей остаётся NaN.

## noisy

Слабое сглаживание: $v^{k+1}=0.75v^k+0.25\operatorname{mean}_{u\in N(v)}u^k$. Вершины на границах и non-manifold рёбрах фиксируем и исключаем из оценки смещений. Считаем расстояния от исходной позиции после первого и третьего шага: $r_1,r_3$.

Смещения делим на диагональ или среднюю длину инцидентных рёбер. Отношения ограничены сверху 100. Один из признаков — $\max(r_1-r_3/3,0)/s_{local}$. Это отклик на сглаживание, а не доказательство наличия шума: острые корректные детали тоже могут двигаться.

## artifacts

Для каждого ребра считаем медиану длин инцидентных рёбер у обоих концов $m_u,m_v$:

$$r_{uv}=\frac{l_{uv}}{\max((m_u+m_v)/2,10^{-12})}.$$

Само ребро тоже входит в медианы. Это отличается от медианы всех соседних рёбер без рассматриваемого ребра. Берём p95/p99 и доли $r>2$, $r>4$.

Компоненты считаются по общим индексам вершин, без склейки одинаковых координат. Основная компонента — с наибольшим числом граней. Мелкая — меньше `max(10, int(0.001*N_faces))` граней, кроме основной. Далёкая мелкая компонента находится дальше 0.1 диагонали от центра основной; центр — среднее центров её треугольников. Это не проверка смысловой связи объектов.

## Изображения и fusion

PNG состоит из сетки 2×3. DINOv2 ViT-S/14 извлекает 384 признака каждого ракурса. Для mean/max берём $z=[mean(z_1,\ldots,z_6),max(z_1,\ldots,z_6)]$: получается 768 чисел. Конкатенация всех ракурсов даёт 2304. DINOv2 заморожен, обучается CatBoost поверх готовых признаков.

В fusion признаков склеиваем визуальный вектор с геометрией. В fusion вероятностей используем $p=\alpha p_{image}+(1-\alpha)p_{geometry}$; это разные опыты. У simple есть ещё смешивание с прежней связкой ResNet18 + CatBoost.

ResNet использует sigmoid и бинарную кросс-энтропию отдельно по меткам. С весом положительного класса: $L=-[w y\log\sigma(z)+(1-y)\log(1-\sigma(z))]$. `pos_weight` считаем по train, не по validation/test.

## MIL — пока гипотеза

DINOv2 patch tokens объединяются из 16×16 в 8×8 на каждом из шести ракурсов. Голова получает 384 участка. Сравниваем mean, max, top-8 и attention: $\alpha_i=softmax(a_i)$, $s=\sum_i\alpha_i s_i$. Обучение идёт только по метке объекта. Attention показывает вес участка в агрегации, но не является разметкой дефекта и не гарантирует положительного вклада.

## Интерпретация

Feature importance и SHAP объясняют поведение модели, а не причину дефекта. Коррелирующие признаки могут делить важность. У координат embeddings нет прямого физического смысла. Ручные подтипы ошибок в simple — исследовательские заметки, не исходная разметка.
